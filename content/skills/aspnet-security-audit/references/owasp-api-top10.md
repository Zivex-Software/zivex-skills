# OWASP API Security Top 10 (2023) mapped to this skill set

Names and numbering follow the 2023 edition; **check them against the current OWASP edition** before quoting them in a report. "Lead" means a script output to start from; "fix" names the skill that explains the remedy.

| #     | Risk                                            | What to check                                                                                                                   | Lead from                                                                            | Fix                                                                     |
| ----- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| API1  | Broken object level authorization               | every endpoint taking an id enforces ownership or tenant                                                                        | `audit.mjs` ownership candidates                                                     | `aspnet-security` (authorization), `aspnet-data-efcore` (query filters) |
| API2  | Broken authentication                           | token validation (issuer, audience, lifetime, signing key), lockout, session cookies, password hashing                          | `check-security.mjs` SEC004/SEC005                                                   | `aspnet-security` (authn-authz)                                         |
| API3  | Broken object property level authorization      | DTOs instead of entities, allow-listed patch fields, no mass assignment                                                         | `check-api.mjs` API006/API007                                                        | `aspnet-api-design`, `aspnet-security`                                  |
| API4  | Unrestricted resource consumption               | rate limits, page-size caps, body size and timeouts, expensive endpoints                                                        | `audit.mjs` (no rate limiting), `check-performance.mjs`                              | `aspnet-resilience` (rate limiting, timeouts), `aspnet-security`        |
| API5  | Broken function level authorization             | policy on every endpoint and group, admin routes, per-verb protection                                                           | `audit.mjs` endpoint table (`NONE`), `check-security.mjs` SEC020                     | `aspnet-security`                                                       |
| API6  | Unrestricted access to sensitive business flows | abuse of legitimate flows (bulk signup, coupon abuse, scraping): per-flow limits, idempotency, step-up or captcha where fitting | manual review of core flows                                                          | `aspnet-resilience`, `aspnet-api-design` (idempotency)                  |
| API7  | Server-side request forgery                     | user-supplied URLs reach an outbound client                                                                                     | manual search for an `HttpClient` fed by user input (the scripts do not detect SSRF) | `aspnet-security` (input-output, SSRF)                                  |
| API8  | Security misconfiguration                       | developer pages, CORS, HSTS, forwarded headers, verbose errors, default credentials                                             | `audit.mjs` pipeline, `check-security.mjs` SEC001, SEC002, SEC017, SEC019            | `aspnet-security` (http-hardening)                                      |
| API9  | Improper inventory management                   | old API versions, undocumented or debug endpoints, exposed OpenAPI in production                                                | `audit.mjs` endpoint table, `check-api.mjs` API009                                   | `aspnet-api-design` (versioning)                                        |
| API10 | Unsafe consumption of APIs                      | trusting third-party responses: timeouts, validation of responses, TLS, size limits                                             | `check-resilience.mjs`, `check-security.mjs` SEC012                                  | `aspnet-resilience`, `aspnet-security`                                  |

## Using the table in a report

- Group findings by risk number; mark risks you checked and found fine ("API2: token validation reviewed, no findings") so the reader knows the coverage.
- State which risks need runtime or design review the scripts cannot do (API6 especially).
- Do not claim "OWASP compliant": OWASP lists risks, it does not certify (see the claims policy in `zivex-compliance-by-construction` if installed).
